# Workflow details

Canonical flow:

1. `map` / 搭地图: create minimal hooks for zero-background topics.
2. `aim` / 定目标: define why the user reads and what answers are wanted.
3. `match` / 做匹配: map source structure to user aims.
4. `prioritize` / 排优先: decide what to master, skim, defer, or source elsewhere.
5. `intake` / 读进去: read or receive paraphrase for selected items.
6. `compress` / 压出来: user writes understanding; AI critiques against source.
7. `feynman` / 讲明白: explain for durable mastery.

`map` is Step 0, optional but recommended when the user lacks hooks.

Decision heuristics:
- If the user asks for “总结一下” but also wants learning: redirect to `aim` or `match` first.
- If the user provides their own explanation: use `compress` immediately.
- If the user wants to teach, write, present, or deeply master: use `feynman` after `compress`.
- If source evidence is unavailable for critique, say what can and cannot be checked; ask for excerpts or source text if needed.

Do not over-ask. Make reasonable assumptions and create/update records. Ask only when project identity or source access is impossible to infer.
