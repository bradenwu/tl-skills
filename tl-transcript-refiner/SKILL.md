# tl-transcript-refiner — 录音转写纪要整理

把原始听写/ASR 转写稿整理成**忠于原意、结构清晰、口语但不啰嗦**的 Markdown 纪要。

## 核心原则

1. **忠于原意**：不添加原文没有的观点，不改变立场，不做额外评论。
2. **不删实质内容**：只删口语杂质、重复、犹豫、自我纠正；关键观点、例子、数据要保留。
3. **保持原顺序**：不要重排讲话逻辑；只在原顺序内按主题分段和加标题。
4. **保留口语感**：整理后像一份可读的会议/讲座记录，不要改成公文或论文。
5. **通用 Markdown**：输出使用标准 Markdown 标题、列表、加粗和表格；避免依赖特定笔记软件语法。

## 工作流

### 1. 明确输入与输出

- 先确认用户要整理的原始文本范围：全文、某个标题下的部分、某位说话人、或用户提供的选中文本。
- 如果用户指定输出格式或目标位置，按用户要求执行。
- 如果输入很长，可以分块处理，但最终输出要连贯，不要留下“chunk”痕迹。

### 2. 截取处理范围

常见范围边界：

- 标题：从“某讲座/某议题”到下一个同级标题前。
- 自动说话人：`说话人 1/2` 可用于判断讲话段落，但输出时删除。
- 用户选择文本：优先以选择文本作为范围。

### 3. 清理口语杂质

删除或精简：

- 语气词：呢、啊、哈、呃、嗯、哼、哎呀等；表达真实情绪时可少量保留。
- 填充词：就是说、然后呢、那个什么、你看、怎么说呢、对吧、是吧、好不好等。
- 重复表达：同一意思反复说，只保留最清楚的一次。
- 犹豫和自我纠正：如“我们可以……我们应该……我们可以”保留最终确定表述。

不要为了“简洁”删掉观点、例子、数据、人物、机构、时间。

### 4. 修正识别错误

根据上下文修正明显 ASR 错误，尤其是人名、机构名、专业术语、数字和领域术语。

教育/升学类常见例子：

- “延请学习” → “研究性学习”
- “高招” → “高考招生”
- “换歌” → “换科”
- “统练” → 视上下文改为“统测练习”或保留为学校术语
- “上海九大” → “上海纽大”
- “强基计划”“综合评价”“两依据一参考”“学业水平考试”“五大学科竞赛”“少年班”“保送”“双培/外培”“中外合作办学”等术语要准确

对不确定的专名不要强行改；可保留原词或用更稳妥的泛称。

### 5. 处理说话人

- 删除所有 `说话人 1`、`说话人 2` 等自动标注。
- 能推断身份时，在较大段落开头加粗标注一次，例如：
  - `**杨双伟（课程教学中心）**`
  - `**刘成杰（北京科技大学）**`
  - `**主持人**`
  - `**家长**`
- 不需要每个自然段都重复说话人。
- 无法确认身份时，不加标注。

### 6. 结构化输出

- 长讲话用 `##` 划分大主题，用 `###` 划分子主题。
- 如果讲话者明确说“第一/第二/第三”，保留该结构。
- 小标题要短、具体、可扫读。
- 合并碎片短句为完整段落；每段聚焦一个话题。
- 保留演讲者和听众互动、调侃，但适度压缩。

推荐结构：

```markdown
# 标题

## 一、主题

**说话人（身份）**

整理后的正文……

## 二、主题

整理后的正文……
```

如果用户要求更正式，可使用“会议时间、地点、参会人、议题、正文、待办事项”等会议纪要结构；否则优先保留讲座/发言记录风格。

## 输出质量检查

输出前快速检查：

- 没有残留 `说话人 1/2`。
- 没有明显口头禅密集残留。
- 关键数字、时间、百分比、人名、机构名没有丢失。
- 标题层级合理，没有空标题。
- 没有添加“我的总结/我的洞见”，除非用户明确要求。
- 语气仍像讲话记录，而不是被改写成论文或公文。

可用正则/搜索辅助检查：

```bash
rg -n "说话人|呃|嗯|那个|然后呢|换歌|延请学习" output.md || true
rg -n "^#|^##|^###" output.md
```

## 写作风格

- 用自然中文，保留讲座感。
- 句子要通顺完整，必要时补出省略主语/宾语。
- 不要把原话全改成抽象总结；案例和细节是纪要价值的一部分。
- 数据照抄并格式化：如 `80% 多`、`39 个家长`、`2026 年 1 月`、`5.5/6.0`。
- 对敏感或不确定内容不做额外扩散，只按原文整理。

## 常见用户请求示例

- “把这段录音转写整理成会议纪要。”
- “继续处理刘教授讲座部分。”
- “按听写整理原则清理这段录音文字。”
- “把说话人 2 的内容整理成可读的讲座记录。”
- “保留原顺序，去掉口头禅和识别错误。”
